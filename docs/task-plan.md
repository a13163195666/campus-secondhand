# 校园二手交易平台 Web 端任务计划

## 一、计划说明

依据：《前端开发实训》课程考核说明。
方向：Web。
人数：5人。
技术栈：Vue 3、Vite、Vue Router、Pinia、JavaScript、
响应式 CSS、Git、ESLint、Prettier。

成员暂用 M1—M5 代替，请填写真实姓名。
时间暂按12个开发工作日安排，D1为小组确认的启动日。
该排期为建议，最终以教师截止日期为准。

已有代码应先验收，满足标准的任务直接关闭，不重复开发。

## 二、考核要求与项目范围

### 附件明确要求

- 至少3个页面或视图。
- 至少5个有实际意义的Vue组件。
- 使用Vue Router。
- 至少一个表单及表单验证。
- 包含列表数据处理。
- 搜索、筛选、排序、分页中至少实现两项。
- 至少一次共享状态管理。
- 至少一次数据持久化或Mock数据。
- 适配桌面端和手机端。
- npm install、npm run dev、npm run build能够执行。
- 每人参与开发，并能解释自己负责的代码。
- 阶段验收须有至少3个主要页面和1个完整核心流程。

### 本组建议实现范围

页面：
1. 商品首页。
2. 商品详情。
3. 发布商品。
4. 个人中心。
5. 我的订单。

核心流程：
卖家发布 → 买家搜索浏览 → 查看详情 →
模拟下单 → 卖家确认交易完成。

使用Mock数据和localStorage。
买家、卖家使用可切换的本地演示身份，不是真实登录。
页面明确标注模拟交易，不接真实支付。

先完成核心范围，再考虑图片上传、分页、真实接口。
实时聊天、物流和真实支付不纳入本期任务。

## 五、关键数据和交易规则

商品字段：
id、title、price、category、condition、description、
image、sellerId、status、createdAt。

订单字段：
id、goodsId、buyerId、sellerId、
titleSnapshot、priceSnapshot、status、createdAt、completedAt。

收藏字段：
userId、goodsId。

商品状态：
- available：在售。
- offline：下架。
- sold：已进入模拟交易，不可再次购买。

订单状态：
- pending：待完成。
- completed：已完成。

模拟下单同时创建pending订单并将商品改为sold。
只有卖家可确认订单完成。
保存失败不得显示交易成功。
暂不实现取消、退款及跨设备交易。

## 六、组件建议

按实际职责拆分，不能为凑数量拆分无意义组件：

- AppHeader：导航。

- GoodsCard：商品卡片。
- GoodsFilters：搜索、筛选、排序。
- GoodsForm：发布和编辑表单。
- EmptyState：空状态。
- FavoriteList：收藏列表。

## 七、GitHub协作规则

1. 每项任务建立Issue，填写任务ID、负责人、验收清单。
2. 从最新main创建feat/模块名、fix/问题名或docs/主题名分支。
3. 小步提交，提交和PR关联Issue。
4. PR至少由另一位成员审阅，组长协调合并。
5. 共享store和字段改动由M4协调；个人中心由M4整合。
6. M3负责详情页，M5的下单入口先沟通再接入。
7. 合并前运行lint、格式检查、构建及相关功能验证。
8. 每日同步完成项、阻塞和下一步；D5提前集成一次。
9. 不提交node_modules、密码或访问令牌。

完成定义：
代码已合并，验收通过，文档和日志已更新，
负责人能够解释实现及边界。

## 八、测试重点

- 标题空白、价格为零、负数及非法小数。
- 搜索、分类和排序组合。
- 无匹配商品、无效商品ID。
- 修改或下架非本人商品。
- 购买自己的商品、已售商品及重复下单。
- 订单状态更新及刷新后的数据一致性。
- 缓存损坏和保存失败反馈。
- 桌面与手机布局。
- 全新环境安装、启动、构建。

常用检查：
npm ci
npm run dev
npm run lint
npm run format:check
npm run build

另核对附件要求的npm install能够执行。
