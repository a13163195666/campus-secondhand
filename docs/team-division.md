## 0. 一分钟读完的骨架

| 阶段 | 目标 | 通过标志 |
| --- | --- | --- |
| 一 · 地基 | 路由、导航、数据契约、目录结构立起来 | 集成点 1：五个地址都能打开，不白屏 |
| 二 · 各页开发 | 五个人并行填自己的页面和组件 | 集成点 2：首页有数据、点卡片能进详情 |
| 三 · 打通流程 | 发布 → 首页可见 → 详情 → 下单 → 完成 | 集成点 3：全流程走通，刷新数据还在 |
| 四 · 收尾 | 手机适配、构建检查、文档、答辩 | 集成点 4：`npm run build` 通过，375px 不溢出 |

**三条铁律**

1. **数据契约先冻结**：字段名由 M4 定，其他人只读不改，要改必须先说。
2. **组件归属唯一**：一个 `.vue` 文件只有一个负责人，别人要用就调，不要复制一份改。
3. **到点不通就降级**，不追完美，先把主流程跑通。

## 1. 共用约定（开工前一次性确认）

| 项 | 约定 |
| --- | --- |
| 分支 | `feature/leader`、`feature/home`、`feature/pages`、`feature/data`、`feature/profile` |
| 合并方式 | 各自推分支 → 在 GitHub 提 PR → 组长审核 → 合并到 `main` |
| 目录 | `src/components/`、`src/views/`、`src/stores/`、`src/data/`、`src/router/` |
| 命名 | 统一用 **product**，不用 goods / item / commodity |
| 禁止提交 | `node_modules/`、`dist/`、`.env`、令牌 |
| 提交信息 | `feat: 做了什么` / `fix: 修了什么` / `docs: 文档`，不写 "update" |
| 验收口径 | 每条任务的验收必须是一个**能点到的页面动作**或一条**能跑的命令** |

### 商品字段契约（M4 定稿，全员遵守）

```js
{
  id: 1,                    // Number，唯一
  title: "二手高等数学教材",  // String，非空
  price: 25,                // Number，> 0
  category: "教材",          // String，取自固定分类
  condition: "九成新",       // String
  description: "九成新…",    // String
  image: "/images/x.jpg",   // String，可为占位图
  sellerId: 101,            // Number，当前模拟用户
  status: "available",      // available | offline | sold
  createdAt: "2026-11-13T10:00:00" // ISO 字符串
}
```

| # | 做什么 | 产出 | 验收 | 卡住怎么办 |

| M1-4 | `main.js` 装配 Pinia/Router | 应用入口 | 控制台无报错，Vue DevTools 能看到 store | — |

**你的额外原则**：不要替别人写他的页面。你只做骨架、接口和集成，页面内容交给负责人，否则答辩时他说不清自己的代码。

## 3. M2 · 首页（列表 / 搜索 / 筛选 / 排序）

| # | 做什么 | 产出 | 验收 | 卡住怎么办 |
| --- | --- | --- | --- | --- |
| M2-1 | `HomeView.vue` 渲染商品列表（≥8 条） | 首页 | 打开 `/` 能看到 8 张卡片 | 数据没给到就先在页面里写死 3 条，接口好了删掉 |
| M2-2 | 调用 M3 的 `ProductCard` 组件 | 卡片列表 | 卡片显示图片、标题、价格、分类 | 组件没好就先写临时 `<div>`，别自己复制一份 |
| M2-3 | `SearchBar.vue` 关键词搜索 | 搜索框 | 输入"教材"只剩相关商品；清空恢复全部 | 用 `filter + includes`，不做模糊算法 |
| M2-4 | 分类筛选 | 下拉或标签 | 选"电子"只剩电子产品；"全部"恢复 | 分类写死在 `products.js` 里，不动态生成 |
| M2-5 | 价格排序 | 排序按钮/下拉 | 升序时第一个最便宜，降序相反 | 用 `sort((a,b)=>a.price-b.price)` |
| M2-6 | 空结果提示 | 空状态 | 搜不到时显示"没有找到相关商品" | 用 M3 的 `EmptyState`，没有就写一行文字 |
| M2-7 | 点击卡片跳详情 | 链接 | 点第一张卡片进入 `/product/对应id` | 用 `<RouterLink :to="\`/product/${p.id}\`">` |

**只展示在售商品**：列表要过滤掉 `status !== 'available'` 的数据。

## 4. M3 · 详情页与公共组件

## 5. M4 · 数据与交互（Store / 持久化 / 发布 / 个人中心）

| # | 做什么 | 产出 | 验收 | 卡住怎么办 |
| --- | --- | --- | --- | --- |
| M4-1 | `data/products.js` 提供 ≥8 条示例数据 | 假数据 | 至少覆盖 3 个分类，含 1 条已售 | 图片用占位图路径，不找真实图片 |
| M4-2 | `stores/productStore.js` | Pinia store | `getProducts()` 返回数组，控制台可调用 | 先只做 state + getters，actions 后补 |
| M4-3 | 暴露统一方法：`getProducts`、`getProductById`、`addProduct`、`updateProduct`、`removeProduct` | 接口 | 每个方法都能在页面里调通 | 方法名不擅自改，改了要全员通知 |
| M4-4 | `localStorage` 持久化 | 刷新不丢 | 发布一个商品，刷新浏览器它还在 | 用 `watch` + `JSON.stringify` 存，读取时 `try/catch` |
| M4-5 | 坏缓存回退 | 容错 | 手动把 localStorage 改成乱码，页面仍能启动 | 解析失败就回落到 `products.js` 初始数据 |
| M4-6 | `PublishView.vue` + `ProductForm.vue` 表单与校验 | 发布页 | 标题空、价格为 0 或负数时有错误提示，不能提交 | 校验写在 `submit` 里，不用第三方库 |
| M4-7 | 提交后调用 `addProduct` 并跳转 | 闭环 | 发布成功后首页能看到新商品 | 成功后 `router.push('/')`，不留在空白页 |
| M4-8 | `ProfileView.vue` 我的发布 | 个人中心 | 只显示 `sellerId === 101` 的商品 | 按 sellerId 过滤，别显示全部 |
| M4-9 | 下架 / 删除 | 操作按钮 | 下架后首页不再显示；删除后彻底消失，刷新也不回来 | 下架是改 `status`，删除是 `removeProduct` |

**字段有任何改动，必须先在群里说，再由 M4 统一改。** 其他人不要自己动 `products.js` 的结构。

## 8. 降级顺序（越靠前越先砍）

1. 收藏功能（页面按钮先隐藏）
2. 价格排序（只保留搜索 + 分类）
3. 订单"确认完成"（只保留下单）
4. 图片展示（统一换占位色块）
5. 手机适配（先保桌面演示）
6. 发布页表单美化（保留校验逻辑）

**永远不砍**：五个页面可访问、至少一个表单带校验、搜索或筛选至少一项、Pinia 共享状态、localStorage 持久化、`npm run build` 通过。这六条是考核硬指标。
